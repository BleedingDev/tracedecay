Apply after the original host fixture patch and its `62d2ae624cd19491782d2d92ce4ab84a66c445bb8d71393927e1952adbfea33c` correction delta. Its exact base module is SHA256 `435ebaa7a01ada83d1f46a9bd8b782649e0467c0acde04fccc17b8171ba3647e`; the consumer module is `fe909dd97093091d6b98acf73e6f0ba6954ee7450810b2777344bc3f9fc325ce`. The parent test file is unchanged. Both earlier mirrors remain frozen.

Compile dependencies are the approved `e361d534` context-evidence facade and the `28abfdf1` layered OperationControl/OwnedExactScope reexports. The numeric declaration API is not used until a fresh actual Health response can establish its acceptance conditions.

The consumer identifies the final JSON payload position using the same unique-JSON rule as production `tool_json_payload`, retaining the original index after prepended warnings. Zero, multiple, mismatched, or nontext payload positions remain unavailable. The production projector's complete decoded result and semantic classifications are durably saved separately from exact raw CLI stdout and all text blocks. No renderer, metrics, warning, or block is removed. The previous inline advisory observation is represented inside the durable full projection artifact, avoiding another large event payload.

The trace reader receives the actual delivered `recall_trace.request_id` and `trace_ref`, actual matching advisory/replay provider registration, and all seven delivered destination-scope fields. Store resolution uses the already observed registered project/store records, the existing persisted profile authority, and the production profile-sharded path resolver. It rejects missing/ambiguous store records, wrong physical project/profile, unsupported storage layout, path traversal, canonical redirects, or disagreement with the production resolver. It never scans for a latest trace or guesses a request identity. Missing producer correlation or missing retained evidence stays unavailable.

The ledger read is a separate read-only evidence operation with its own original 5-second control, begun after the sole scheduled recall command; it does not reuse, reset, or extend the provider deadline. Raw command start/end remains the recall action's host-request timing. Overall fixture duration, post-query evidence capture, and retained evidence read each retain separate measured timing.

This delta deliberately does not resolve native SessionStart bootstrap or source-before-boundary ordering, fresh Health pin/effective-limit binding, documentation delivery, full CLI wrapper token accounting, five-stage comparison candidate attribution, or public source controls. Delivery and successful provider completion remain unavailable/false as in the base, and provider contact is not inferred from a retained trace. Source/canonical revisions are not changed.

Validation: rustfmt parsed/formatted the draft module; rustfmt --check passed for the parent/module pair; git apply --check --whitespace=error passed against the exact frozen correction mirror. Four authored low-cost tests cover warning/metrics preservation and actual payload position, absent/duplicate/nontext payload refusal, complete destination scope even for empty history, and provider/revision/scope mismatch refusal. They have not been compiled or run. No held-out case JSON, model output, provider result, or evaluation was read or executed.
