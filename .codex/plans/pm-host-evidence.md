# Host authority and mounting evidence

Audited `6010f31e7` in `feat/pluggable-memory-providers-v2`, for `pm-host-audit` in graph `pluggable-memory-compat-v1`. Source inspection only; no Cargo/model runs, source edits, configuration changes, restart, commit or push. This document is the lane's only write. Plan status remains root-owned.

The smallest implementation extends the existing registry, registered session store, observation journey and cognitive recall mount. Active selection is still Native-only. Canonical observation, repository-provenance and deletion authorities already exist, but their mere existence does not grant session-A history to session B. The missing producer is a bounded host authorization that joins those authorities to the destination exact scope, retaining original source identity and current deletion state. Two incompatible repository/worktree identity encodings and ingestion-time provenance make an unverified join unsafe.

## Actual mounted call chains

### Registration and observation

1. `project_composition.rs::resolve_memory_provider_activation` (190) reads the pinned runtime configuration. It refuses an NCM observer without `memory_provider_native_enabled`; the activation enum has only `Disabled`, `NativeObserver`, `NativeActive` (68). Its mountability check accepts only `MountableProviderKindV1::Native` (249).
2. `project_code_index_authorities` (2577) obtains the authoritative project ID and `tracedecay_code_index_runtime::resolved_scope_for_project`. `mount_project_memory_provider_host` (404) runs after the cache miss, at the existing core capability admission point (1352). There is no reason to introduce a provider route before this point.
3. That factory always constructs a Native application port for enabled participation (467), inserts the Native observation mount first (432), and optionally calls `construct_ncm_observer` (450). NCM construction failure is currently logged and ignored because that provider is optional. Active-provider failure must instead remain a typed failure of the selected lane.
4. Registry `ProjectMemoryProviderComposition::compose_with_observers` delegates to `compose_selected` (`registry/src/lib.rs:401,418`). `SelectedProviderActivationV1`, `SelectedRegistration`, and `MountableProviderKindV1` still contain only Native. `register_selected` (903) validates the adapter descriptor identity, registers the configured mode/revision, and records authorized recall bindings. Observers receive no recall-binding authorization (`register_observer`, 768). Duplicate identities and capacity are checked before registration.
5. After `admit_session_databases`, root mounts one journey per observation mount (`project_composition.rs:1843`). Position zero receives `mount_and_replay` and mandatory failure handling; later positions receive `mount_observer_dormant` and optional failure handling. Required versus optional must become explicit mount metadata when either provider may be selected; position cannot remain a synonym for Native.
6. `ProjectObservationJourneyV1::replay_canonical_observations` (`observation_journey.rs:2955`) reads `ObservationAdmissionPort::replay_admitted_observations` in bounded pages, starting from the durable journal watermark. `source_record` (3081) preserves stored sequence and observation ID, then `CanonicalObservationAdmissionAdapterV1::decide` (1076) checks project ownership, validates canonical identity, selects user/assistant `facts.kind == message`, sanitizes the delivered envelope, binds settlement/privacy/idempotency, and appends to the existing journal. Provider-native `native_record_kind` is not message eligibility.
7. `RegistryObservationDeliveryAdapterV1::deliver` / `deliver_after_readiness` (1927,1970) use supervised exact-scope readiness and registry observation delivery. Each provider has its own journal, progress, namespace and receipts. NCM's existing `construct_ncm_observer` (`project_composition/ncm_observer.rs:124`) returns its real descriptor limits, exact-scope namespace policy and worker-backed instance proof; reuse that construction/owner path for active NCM rather than making another daemon registry.

### Recall, admission and context

After the authoritative handler succeeds, lines 417–424 invoke `advisory_memory_context_for_call` and `appended_to`. Ordinary canonical context/code/fact/session work remains the same with either advisory provider.
2. `cognitive_recall.rs::advisory_session_binding` (1516) uses the structural session identity or the host-minted MCP connection identity. `ProjectCognitiveRecallMountV1::port_for_session` (1253) installs `SessionExactScopeBindingV1` (842). Every profile/project/repository/worktree/reference/resolved-digest field remains host-owned. `provider_agent_session_id` (`observation_journey.rs:842`) hashes that full scope plus the canonical session. Session B therefore has a distinct exact namespace even on the same checkout.
3. `advisory_context_recall` (`cognitive_recall.rs:1763`) creates the application request, then `ProjectCognitiveRecallPortV1::recall_uncounted` (`registry/src/recall_port.rs:587`) validates live cancellation identity, derives exact scope, reads selected execution shape from the registry, clamps budgets, and routes through the existing invocation boundary and `registry.route_active`. The fabric performs the pinned revision/mode/capability check, fresh handshake and provider call; do not duplicate that routing authority.
4. Giving NCM that binding or deleting its session fields would not create an A→B grant.
5. The application port currently constructs `AdmittedTemporalQuery::current` (`recall_port.rs:654`); `CognitiveRecallRequest` has no temporal/exclusion fields (`contracts/src/memory/recall.rs:45`). Registry admission already represents current/as-of/interval/history. Exposing the common time/exclusion profile requires an additive contract and real host mapping, not just an adapter change. Reference-only candidate content is also explicitly withheld by this port (887); the present product path needs inline admissible content or a real content resolver.
6. Root hydrates provenance (`cognitive_recall.rs:1878`), applies the untrusted-text/metadata gate, compiles a token-bounded context pack, and retains the reconciled explanation trace (`context_pack`, `appended_to`, 3093,3150). Canonical host evidence is packed before provider quota. Provider identity, admission failures and host withholding remain visible. This pipeline is already provider-neutral except for the mounted attestation implementation and Native limits supplied at construction.

### Common canonical fact lane is already present

`mcp/tools/handlers/graph.rs::handle_context` (821–846) independently runs `context_memory_outcome` alongside code search, before any advisory-provider append. `graph/context_support.rs::context_memory_matches` (282) calls `cg.project_memory_application()` and `search_project_memory_facts` with the canonical owner, a search query and `FactReadControl` tied to the admitted deadline/cancellation. There is no Native advisory activation dependency. `include_memory` defaults to true, `memory_limit` to 3 (maximum 10), and minimum trust to 0.5 (`context_support.rs:174`). Root renders the canonical hits into the handler result (`graph.rs:960`); `cognitive_recall.rs::json_member_evidence` (2444) and `markdown_block_evidence` (2501) identify the canonical memory section as required `NativeFacts` host evidence. This authority label means canonical fact authority, not activation of the Native advisory adapter.

Therefore NCM active can receive the same common project-fact lane without activating Native advisory memory. Reuse this producer; no new fact store or second canonical-fact fallback is needed. The comparison must pin the same include-memory setting, query, trust filter, limit, source snapshot and read controls for all provider lanes, and report that lane's contribution/cost separately. Any additional profile-fact or alternate canonical read that is currently reachable only through Native's adapter must either move into the common host producer for both providers or be excluded from the matched advisory profile; do not count it as a Native advisory advantage.

**Duplicate attribution rule:** one accepted canonical owner+fact identity/source revision belongs to the common fact lane once. A Native advisory candidate referring to that same canonical fact is excluded from additional provider contribution and useful-recall credit, with a recorded duplicate reason. For the matched advisory population, provider-returned canonical facts outside the common result set must also be handled by the identical common policy rather than become provider-specific extra evidence. Genuine provider-local derived content keeps provider/source lineage and is not silently promoted to a canonical fact. The current `host_evidence` projection splits rendered JSON/markdown into host blocks, while provider selection deduplicates within the provider candidate set; that does not establish identity-based cross-lane deduplication. The missing small producer is typed canonical fact identity/revision metadata carried from `ContextMemoryOutcome` to context assembly/evaluation. Host integration owns the needed `graph/context_support.rs`, `graph.rs` and cognitive packing slices after root assigns them; the Native owner adjusts any adapter-side common-profile exclusion, without changing canonical fact storage.

### Identity and source-time gaps that must be resolved

The two identity producers are incompatible by construction:

- Session provenance: `repository.<hash>` / `worktree.<hash>`, derived with a project-domain salt and distinct namespace tags from an authoritative marker context (`sessions/src/repository_provenance.rs:135–162`).
- Recall/code-index scope: `repository.daemon.<hash>` / `worktree.daemon.<hash>`, derived by the existing daemon identity functions (`code-index-runtime/src/code_index_scheduler/identity.rs:288–343`). `project_composition.rs:2592` consumes this `ResolvedScope`.

No observed method binds those two representations. Byte comparison will fail for legitimate sources; prefix replacement or path equality would fabricate authority. The root-reviewed producer must supply an explicit binding between the current admitted marker/provenance identity and the mounted daemon scope, or retain the daemon origin scope through the canonical capture boundary. Source selection can then compare historical stored provenance in its own namespace to the admitted current provenance identity while destination provider calls retain the full existing `OwnedExactScope`. No new global identity cache is required.

There is an additional source-time limitation: `sessions/src/observation.rs:530–545` sets `ingested_at = now_micros()` and captures the repository then. A catch-up transcript may contain older messages. A capture on branch B at ingestion cannot be asserted as proof that an older message originated on branch B. `CanonicalObservationFactV1::Session` contains paths and location labels, not a typed original branch identity. The history producer must distinguish contemporaneously admitted source scope from later catch-up evidence, or obtain retained authoritative source-session scope from an existing producer before granting branch-sensitive reuse. Legacy rows lacking that proof must remain explicitly ineligible/partial; reopening today's checkout cannot repair their origin retroactively.

### Required producer/consumer handoff

Root settles the common grant/source contract first. The smallest producer is a focused history module consuming the registered session observation store, current source/anchor disposition authority and an explicitly admitted identity bridge. It must produce:

1. Destination full exact scope and host authorization/policy identity, separate from original native provider/session/source-key/observation/range/generation/revision/anchor identities.
2. Eligible original checkout/reference evidence and its availability. Missing, conflicting, foreign or only ingestion-time evidence cannot silently become origin proof.
3. Original observed/occurred time plus separately named ingestion time; retained validity/correction lineage; current deletion/retention disposition and a revalidation point before replay and recall. Unknown time remains unknown.
4. A bounded page/progress result with accepted, withheld, ineligible and incomplete coverage. The current journey's single source-stream watermark describes delivery to source namespaces; destination-B replay needs independent progress keyed to selected provider/generation and destination scope, using existing durable journey machinery.
5. Stable idempotency from original source identity/revision plus destination grant/provider namespace. A new admission UUID alone is not replay identity. Preserve original source keys for deletion even when copies live in B and later C.

The existing journey already preserves sanitized canonical payload and settlement identity. Its current `decide`/`source_record` check only project ownership and derive an exact scope from **the mount's present scope** plus the source session (`observation_journey.rs:1090,3086`). That is a delivery implementation, not historical checkout authorization. Do not use it to infer an origin scope or to authorize a new namespace. Destination sharing belongs before provider delivery, with original source attribution retained in the common envelope.

## Provenance and deletion boundaries

`MountedHostProvenanceAuthorityV1` (`registry/src/recall_provenance_hydration.rs:634`) recognizes three host evidence grammars:

- `source:<relative path>#L…`: root bounds and canonicalizes the file inside the admitted checkout and checks line count (`cognitive_recall.rs:1295`). This checks a current file range, not historical source revision/content identity.
- `session:<id>#…`: authority refuses any session other than the requesting session (668), then root's `MountedSessionEvidenceStoreV1` always returns typed `Unavailable` (1343). There is no mounted ordinal lookup. An A-origin citation in B needs an explicit granted-source resolver, not removal of the session equality check.
- `record:<id>`: root reads canonical project-memory facts by owner-bound `ProjectMemoryFactIdV1` and accepts only an available projection (`cognitive_recall.rs:1119`). This is not a generic canonical observation/anchor resolver; formatting an observation ID as `record:` will not make it valid.

Provider-local attestation exists, but its mounted implementation only recognizes Native staged-reference grammar (`cognitive_recall.rs:1384`). It confirms that product code mints that grammar, not that canonical content exists; the trust tier stays `ProviderAttested`. Inject a selected-registration-owned attestation/source mapping, or use a genuinely host-resolved canonical observation/anchor reference from the history producer. Never manufacture a `session:` reference from the requesting session, and never upgrade provider attestation to host confirmation.

Deletion has three distinct existing scopes:

| Surface | Existing behavior | Missing common product wiring |
|---|---|---|
| Canonical fact remove/feedback | Existing retained memory application mutates canonical fact state under its fact owner. | This must not become a provider operation or be triggered implicitly by provider feedback. |
| Canonical observation/anchor disposition | Existing anchor disposition/tombstone/derivative authority and session retention machinery establish current source unavailability. | Bounded authorized source-state projection into replay/recall, correction lineage and all copied-provider targets; immutable observation admission alone does not provide it. |
| Observation journal `forget_source` (`memory-observation/src/sqlite/retention.rs:218`) | Zeroes journal content/bindings, terminalizes pending delivery, clears withheld rows, preserves receipt accounting and checkpoints WAL. | It does not invoke provider `DeleteBySource`, erase already-learned derived provider state, or revoke a fresh switched-provider replay by itself. |
| Provider API `DeleteBySource` (`provider-api/src/lib.rs:744`) | A declared provider-local operation/capability exists. | Real adapter effects, public attributed routing, original-source fanout and durable replay/snapshot anti-resurrection fences must be supplied by their assigned lanes. |

Current journal forget keys are minted from source exact scope plus canonical session (`observation_journey.rs:1385`). For A→B replay, do not regenerate the source's deletion identity from B. Canonical privacy deletion must dominate history and switching; provider-local deletion must remain separately described and retained so replay into that provider cannot resurrect its deleted source.

## Real feedback seam

The existing public `tracedecay_fact_feedback` path is canonical: `application_surface/retained.rs:281` decodes `FactFeedbackRequestV1` → retained memory execution → `DirectRetainedMemoryPortV1::execute_feedback` (`retained_owner/memory.rs:266`) → `execute_feedback_on_db` (580) → `record_project_memory_fact_feedback` (615). Its request names `fact_id`, optional expected event, action and canonical memory scope (`contracts/src/retained_surfaces/sdk.rs:149`). It has no provider/candidate attribution and must remain canonical.

At the provider boundary, `ProviderOperation::Feedback` and `feedback.record.v1` already exist (`provider-api/src/lib.rs:736,781`). Registry `route_active` and `ActiveCallPlan` are operation-neutral. No production host call to `ProviderOperation::Feedback` or `feedback.record.v1` was found in root/registry production sources; only registry tests exercise that operation. Thus there is a real low-level routing seam, but no completed public provider-feedback producer.

Use an additive provider-neutral retained application operation and a bounded host control port, then dispatch the common feedback payload through the existing registered provider route. The submitted target must bind producing provider/revision, stable candidate/source identity and original admitted recall/session scope, plus mutation idempotency and caller controls. An arbitrary candidate string or the currently selected provider is not enough. The existing admission/trace ledger is useful evidence but is not a complete stable candidate→source→producing-state authorization store; extend that existing retained outcome seam with the minimal needed attribution rather than create another routing registry. A provider switch must not send old Native feedback to NCM or vice versa. If the original provider is unavailable/disabled or the requested control mode is unadmitted, return a typed refusal until the host explicitly admits that control path; never fallback to another provider or canonical fact feedback.

## Configuration compatibility and migration

Baseline behavior is concrete:

| Legacy configuration | Result |
|---|---|
| Defaults: Native false, NCM observer disabled, empty recall routing | No provider host/adapter/journey; canonical services still operate. |
| Native true, no active provider | Native observation only; no recall route. |

| Native false, any active provider | Typed configuration failure. |

| Active `ncm` or unknown identity | Not mountable; typed failure. |

These settings are canonical registry values requiring daemon restart (`global-db/src/configuration/registry.rs:601–617`). `TraceDecayConfig` defaults and parsing live in `configuration/src/config/mod.rs:51,70,257,341,365`. `MemoryProviderNcmObserverV1` currently stores disabled/enabled plus absolute worker/model-root paths (`domain/src/configuration.rs:1027`); it cannot express independent NCM active participation.

Root/contract should choose one additive neutral participation/configuration representation with explicit precedence: absent new representation preserves the table above; an explicit new representation can select NCM with Native advisory disabled; contradictory simultaneous legacy/new selections must be rejected or have a documented validated migration, not silently merged. Retain existing paths/data and default-off behavior. Preserve separate selected-provider identity and observer participation. Active NCM preflight must truthfully report missing worker/model/readiness; ordinary startup must not download a model. Do not rename legacy settings in place or silently promote a legacy observer.

## Focused acceptance/negative cases for downstream owners

- Both selected configurations yield nonempty admitted context through the actual `tool_dispatch` path in Claude and Codex session A→B journeys, with the other provider disabled and then observing; observer changes cannot change selected output. Canonical project-fact hits remain identical under both selections and provider duplicates receive no extra contribution/quality credit.
- Unknown/unregistered/observer-only/wrong-revision provider selection fails before contact. Default disabled creates no provider worker, state or journal. Selected failure is visible and attributable.
- A→B preserves source provider/session/key/record/generation/revision/time, while provider calls carry B's full exact scope. B→C/restart replay is idempotent and coverage is explicit.
- Different profile/project/repository/worktree/reference, stale resolved scope, absent source-session grant, missing/partial identity evidence and delayed-ingest branch ambiguity do not grant reuse. Include the legitimate case where the two identity encodings differ, proving the explicit authority bridge rather than string comparison.
- A-source citations in B require the granted source resolver; fake `record:` observation IDs, invented session ordinals, arbitrary provider-local grammars, external symlinks and wrong source revisions fail. Provider attestation remains labelled as such.
- Historical requests retain original validity; deleted/redacted/expired canonical sources cannot recall or reappear after replay, switch, snapshot restore or rollback. Provider-local deletion and journal forget are tested separately from canonical deletion. Deletion racing replay must have an explicit fence and visible partial effects.
- Feedback binds the producing provider/candidate/source and does not mutate canonical fact trust. Duplicate feedback/correction/delete yields stable effect accounting; unknown mutation completion is not blindly retried. Old-provider feedback after switching is never redirected.
- Live cancellation/deadline covers provider execution, source authorization, hydration and retention of trace/feedback results. Process shutdown actually reaches the existing worker owner; a stopped wait is not reported as a stopped child.

Existing direct suites in registry `tests/recall_port.rs`, `recall_admission.rs`, `recall_provenance_hydration.rs`, `supervised_readiness.rs`, `adversarial_mounted_dispatch.rs`, plus root observation/cognitive tests, already cover substantial refusal and containment behavior. Reuse those and the existing real-host fixtures; this audit did not rerun them.

**Stop/handoff:** the common contract can now name the identity bridge, original-source grant, current source-disposition projection and attributed control operation as real required producers. Existing canonical store, anchor lineage, journal and routing capabilities should be reused. Native-only mounting, a declared feedback enum or an immutable source anchor must not be reported as completed interchangeable-provider behavior.
