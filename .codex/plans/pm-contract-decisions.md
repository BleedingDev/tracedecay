# Common memory implementation decisions

Root-issued implementation handoff for pm-contract. The user has authorized execution of the complete Native/NCM graph. These decisions settle the audited semantic gaps; preserve the existing MemoryProvider/ProviderCall boundary and canonical contracts.

1. Introduce a named common advisory profile requiring the existing health, observe, recall, feedback, maintenance, inspection, correction, delete-by-source, snapshot export/restore and replay capabilities. Keep V1 legacy negotiation behavior; completing the new profile must not silently change old default-off settings. The profile is an explicit required capability/metadata value, not a provider-name shortcut. Native canonical fact projection stays a separately declared legacy/optional extension outside common advisory comparison.
2. The shared profile accepts canonical committed session messages and settled source-edit, test-execution and feedback-outcome observations already represented by the common corpus. Other existing observation kinds remain explicitly declared extensions. Project non-message structured observations through bounded supported evidence fields; never call arbitrary raw JSON a recalled message. Canonical fact promotion remains verification-only under its own authority.
3. Reuse canonical recall fields/modes/budgets/exclusions and terminal/effect types. Add optional/defaulted temporal/exclusion options to application CognitiveRecallRequest with validated builder/accessors; keep its old constructor and old serialized form valid. Host consumers must no longer hard-code current/empty exclusions. Unknown requested modes/required extensions fail; every required known mode is implemented by both.
4. Add the minimum provider-neutral owned source/validity/history/control values required by both adapters. Original source identity distinguishes canonical provider, canonical session, source key, native stable record, canonical observation ID, actual source revision and content digest. Envelope schema version is never source revision. Missing legacy revision/validity remains unknown. Source sequence, occurred time and ingestion time stay separate.
5. Original exact scope and destination exact scope are separate values. Original evidence can be explicitly unavailable for legacy or delayed catch-up data; never invent an OwnedExactScope from the current mount. A history grant requires proved original authority and carries the host-admitted relation plus original source references and current source disposition. It is a typed claim whose authority the host validates against its existing marker/observation/disposition ports; constructing it or hashing it never proves authorization. No new signing service, identity cache, database authority or scope-wide provider namespace.
6. Temporal validity uses recorded start inclusive/end exclusive; current/as-of/interval/history honor supersession and ordinary revocation flags. Observation occurrence is not automatically assertion validity. Canonical deletion/redaction/retention fences and provider-local privacy tombstones dominate every mode, including include_revoked=true. Ordinary revocation metadata remains distinct from privacy deletion. No retained proof produces explicit unknown/partial coverage rather than fabricated current or historical truth.
7. Lifecycle targets bind producing provider, exact original/delivery scope, stable source/revision and stable provider reference or retained recall/context attribution. A request-scoped candidate ID alone is insufficient. Correction checks expected target revision and retains lineage; replacement closes the previous validity interval and preserves the original observation/receipt.
8. Feedback consumes settled helpful/harmful/ignored/corrected/superseded signals with bounded weights/evidence from the existing lifecycle contract. Its effect is provider-local and inspectable; it cannot change canonical trust. Ranking algorithms may differ, but real settled effects and idempotency must be observable. An explicitly neutral ignored signal can record a truthful no-change result, not a claimed learning effect.
9. Deletion records a provider-specific source fence in the existing host observation journal before provider dispatch; canonical source deletion reads the existing canonical disposition authority. Offline intent is not verified erasure. Fresh observe, replay, correction and restore must honor the current fence. A new source revision may reappear only through an explicitly admitted revision transition permitted by the requested deletion mode/policy; new bytes or a new key are insufficient.
10. Every actual mutation has durable operation accounting and monotonically increasing live generation. Same delivery key/request reports the original committing operation/receipt. Source-already-applied replay is distinct from a new delivery-key duplicate. Unknown commit status stays unknown until reconciliation; cancellation after dispatch cannot claim no effect without proof.
11. Snapshots remain provider-specific and versioned, exact-scope bound and atomically restored. Restore never regresses live generation or aliases discarded public targets. A fresh destination needs a current host-authority disposition read/revalidation before ready recall. That read covers changes since the snapshot; an unchanged checkpoint is valid when no intervening deletion occurred. Provider generation, source disposition revision and snapshot generation are separate orderings, not numerically interchangeable freshness proofs. Provider switching uses canonical history replay, never cross-provider internal snapshot loading.
12. Health, inspection, export and recall are reads. NCM pending privacy recovery completes as an explicit lifecycle/readiness transition before those reads are admitted. Maintenance implements the common tasks with real bounded scan/effect counts; provider-specific algorithm controls are optional.

Implementation boundaries: API values stay provider-neutral and reuse existing generated contract types. Preserve the API's dependency-light design; ask root for any exact manifest patch instead of applying it. Prefer additive types/modules and builders over a second serialized protocol. Canonical schema/binding generation must follow existing scripts; regenerate only semantic consumers. Root approves shared-interface diffs and runs scoped validation before downstream writers start.
