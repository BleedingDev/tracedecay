# pm-provider-control-routing

The reviewed registry/fabric changes are applied. The complete changed fabric invocation suite, exact original-provider control regressions, and registration profile assertions passed in the combined verification. Public retained control dispatch and authority resolution remain the host consumer's work.

One registration owner prepares an unapplied registry/fabric patch and direct tests. The existing supervisor remains the quarantine authority; the later host dispatcher must acquire and hold its readiness guard. Observer controls do not grant recall authority. Provider identity and registration revision remain exact and independent of current selection.

Registration metadata retains requires_common_advisory_profile directly from the host composition argument so admission can enforce the matched profile without guessing from provider names or replies. Root reviews before application. No recall modules, shared DTOs, host controls, Cargo or operator state changes.
